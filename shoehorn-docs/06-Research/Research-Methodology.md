# Research methodology

## Goal

Competitor/prior-art research should prevent two errors:

1. declaring an idea unique because search was shallow;
2. dismissing Shoehorn because adjacent tools exist.

## Search dimensions

For each concept, search:
- consumer products;
- FOSS;
- OS features;
- academic prior art;
- media APIs;
- upload infrastructure;
- vertical tools;
- old/abandoned software;
- package names;
- patents/trademarks separately when needed.

## Query families

Examples:
- destination-aware file conversion
- compatible media transcoding
- automatic file format adaptation
- file upload repair
- constraint based transcoding
- device-aware conversion
- minimum-change conversion
- compatibility converter
- content adaptation

## Evidence hierarchy

Prefer:
1. official docs/source repository;
2. research paper;
3. reputable app store;
4. credible third-party review;
5. forums only for user evidence.

## Record

For every competitor:
- research date;
- source URLs;
- direct facts;
- inferred threat;
- exact overlap;
- exact difference.

## Negative claims

Search cannot prove a universal negative.

Never write:
> “No one has ever done this”

based only on no result.

Use:
> “No obvious incumbent surfaced in this research owning the exact abstraction.”

## Refresh

Re-run before:
- YouTube publish;
- launch post;
- investor deck;
- pricing;
- trademark/name claim.

## Product research vs. novelty research

A product can be worth building without being first.

The key questions:
- Is the problem real?
- Is the abstraction simpler?
- Is the workflow better?
- Is there a durable wedge?
