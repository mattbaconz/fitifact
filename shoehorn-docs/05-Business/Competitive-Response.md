# Competitive response strategy

## If VERT adds destination presets

Do not race on preset count.

Double down on:
- explicit constraints;
- minimum mutation;
- validation;
- profile provenance;
- developer API.

## If CloudConvert adds “make compatible”

Compete on:
- FOSS/local;
- portable profile standard;
- planner transparency;
- OS/browser integrations.

Potentially integrate CloudConvert as an executor instead of treating every processor as enemy.

## If Uploadcare/Filestack/Transloadit add auto-repair

They are strongest B2B threat.

Shoehorn response:
- be execution-provider-neutral;
- let Shoehorn compile policies into their pipelines;
- own registry/constraint language;
- position as compatibility intelligence layer.

## If OS vendors expand native transcoding

This validates category.

Shoehorn focuses on:
- cross-platform;
- arbitrary constraints;
- developer control;
- broader file families;
- profiles.

## If an open-source clone appears

Do not close the core.

Win on:
- maintainership;
- ecosystem;
- verified registry;
- integrations;
- quality;
- brand.

## If users only want explicit conversion

Keep advanced explicit constraints/CLI, but protect destination-first default.

Do not let usage pressure turn homepage into format tiles without evidence.

## Strategic posture

Transform engines are often complements, not enemies.

Shoehorn's best position may be:
> **the planner above all converters.**
