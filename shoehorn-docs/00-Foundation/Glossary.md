# Glossary

**Adaptation** — A transformation sequence whose purpose is to satisfy destination constraints.

**Artifact** — Input/output file plus inspected metadata and provenance.

**Capability** — A property a destination supports or a provider can produce.

**Compatibility** — Artifact satisfies all known hard destination constraints.

**Compatibility profile** — Versioned evidence-backed constraints for a destination.

**Constraint** — Machine-readable requirement such as `max_bytes <= 5_000_000`.

**Constraint compiler** — Converts requirement sources into typed constraints.

**Destination** — App, device, endpoint, browser, workflow, or explicit requirement set.

**Executor/provider** — Component that performs a concrete transform.

**Hard constraint** — Must be true for success.

**Inspection** — Parsing the actual file to determine real characteristics.

**Minimum mutation** — Least-destructive valid transformation path.

**No-op plan** — Input already satisfies constraints.

**Plan** — Ordered transform graph plus expected effects/costs/validation.

**Preference** — Soft objective such as preserve resolution or metadata.

**Profile provenance** — Evidence showing where requirements came from.

**Registry** — Collection of profiles, sources, versions and tests.

**Stream** — Media component such as video/audio/subtitle.

**Transform** — One operation changing artifact state.

**Validation** — Re-inspection and constraint checking after transformation.

**Verified profile** — Profile meeting project verification policy at a recent point in time.
